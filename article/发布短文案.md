# 小红书发布文案

## 推荐标题

一年聊天记录太多？我做了个「后来呢？」

## 正文

聊天记录一多，最难找的往往不是某句话，而是它的后来。

三月说“等忙完去骑车”，四月到底去了没有？一次认真提过的意见，几个月后有没有变成行动？靠关键词搜索能找到“骑车”，但很难把提出、等待、重排和最后落地重新连起来。

所以我做了个聊天年鉴，叫「后来呢？」。把 TXT、MD 或 CSV 放进去，它会整理出这一年聊了什么、哪天最热闹、几点最爱说话，还会寻找跨月约定、重要变化和那些没说完的“下次”。每个事实结论都能点回脱敏后的聊天原文。

底层接入了 Doubao-Seed-Evolving。它最新支持 1M 超长上下文，也针对 Agent / Coding 场景强化了复杂任务编排、长程规划和工具调用。放在这个项目里，作用很具体：尽量把全年聊天放进同一个分析任务，先规划值得看什么，再沿时间整理完整故事线，最后回到原文检查证据——一句话和几个月后的回应，也有机会重新被连起来。

我用 50 条覆盖一整年的虚构消息跑了一次深度模式：3 次 API 调用共消耗 54,165 Tokens，累计耗时约 11 分 53 秒。样例里预埋的 6 条跨月线索召回 6/6，引用的证据编号没有出现无效 ID；最后的审计阶段又修改了 29 处报告细节。这个结果只对应公开样例，不外推到任意真实聊天。

项目也开放了上传和 API Key 入口，可以用自己的聊天记录生成一份。公开样例全部为虚构内容，处理真实记录前也记得先取得相关参与者同意。

项目地址：<https://github.com/jjyaoao/chat-later>

希望大家说过的“下次”，后来真的都有下次。
